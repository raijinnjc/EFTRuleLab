# EFT RuleLab — Checkpoint A

**Research diagnosis and proposed visitor journey. Stop for approval before restructuring.**

The current app accurately exposes its fiscal arithmetic and limitations, but its main sequence inserts a policy counterfactual between the fiscal proof and the decision-evidence question. Its proposed methodological contribution, ARP, sits outside that sequence. Better motion and passing tests do not settle that communication problem.

The proposed journey is:

1. **What can we prove?** Compare the reconstructed FY2022 performance pool with twenty published positive allocations: Test 1 PASS, Rp0 gap.
2. **What can't we reproduce?** Show the independent decision question, four missing input categories and Test 2 INCOMPLETE from the records obtained for this study.
3. **How could verification improve?** Explain proposed ARP: approved inputs, independent derivation before revealing the target roster, comparison of identities and amounts, and bounded outcome recording.

Rule Shift and the other analytical/evidence tools stay available through explicit contextual actions and a shared tool menu. No existing public link, P0 tool or analytical state is proposed for deletion.

## Decisions requested at this gate

- Use the proof / missing decision evidence / proposed review sequence; move Rule Shift into supporting analysis.
- Keep the approved Dusk introduction and continuous fiscal figure, but initially group the five deductions so the pool-versus-ledger comparison leads. All exact inputs and individual locators remain inspectable.
- Give each chapter one job: chapter 01 owns arithmetic, chapter 02 owns missing decision evidence, chapter 03 owns the proposed method. Keep concise independent statuses/limitations where relevant rather than repeating complete explanations.
- Promote existing #protocol into the primary story and make derive-before-reveal central. It remains an unexecuted proposal; no fake replay or access-control system is introduced.
- Reorder the existing tour to Funds → Awards → Verification → Protocol → optional Policy while preserving all five destinations and current controls/state behavior.

These are review choices, not already approved implementation decisions.
