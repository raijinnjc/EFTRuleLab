# EFT RuleLab engineering guidance

Read `docs/product/EFT_RuleLab_PRD_v1.0_Codex.md`, the supplied handoff, `DESIGN.md` and `data/README.md` before product work. The PRD governs fiscal facts, scope and acceptance; the design system is a proposal pending review.

Use Superpowers for design discussion, implementation planning, TDD, debugging, review and verification as applicable. Consult repository-local `ui-ux-pro-max` for visual guidance and `hallmark` when an interface critique is requested. Higher-priority user and session instructions prevail over third-party skill preferences.

Each cloud task already has an isolated environment. Use the existing checkout; do not create Git worktrees unless explicitly requested. Preserve installed skills and existing user changes. Work on a dedicated branch, review the diff and run relevant verification before reporting success. Never merge or deploy without authorization.

Keep source data immutable and provenance explicit. Historical reconciliation is distinct from unavailable historical decision replay; 2021 rules on the FY2022 base are counterfactual. Missing assessment records are not zero scores or government wrongdoing. No synthetic recipients, payments or ecological outcomes.

This bootstrap contains documents and skills only. Do not interpret a document handoff as authorization to implement the application; follow the active user task.
