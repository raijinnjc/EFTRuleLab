# Visual inconsistency audit — before implementation

Baseline: `fc6783a` (main, merged PR #9). Captured actual production React on 9 November 2026 with Chromium, bundled fonts ready, at **1440 × 1000 and 390 × 1000**. Nine views, eighteen full-page captures in [before/](before/). Source Inspector was opened from The Puzzle; the other eight use public routes. Screenshots were visually inspected individually and in desktop/mobile contact sheets. This is an observable composition audit, not an assertion that lint findings equal usability defects.

| Component / aspect | Observable current problem | Proposed correction | Priority / milestone |
|---|---|---|---|
| Puzzle geometry | Four equal-weight monetary blocks precede two separate mini-bars; source-to-award relationship must be assembled by reading | One continuous gross-scale waterfall, explicit denominator break, residual composition and equal-award field | High / Step 3 |
| Puzzle mobile ordering | Three roomy workspace links appear before the heading; inspector is below all charts and boundary copy | Canvas first, compact tool navigation, contextual detail directly below figure | High / Step 3 |
| Puzzle numeric hierarchy | Four similarly sized totals compete with the award sum; labels switch to abbreviations only on mobile | One focal reconstruction, exact selected figure, tabular numbers; exact chart inputs remain available | High / Step 3 |
| Puzzle chart proportion | Two equally sized strips use different denominators but are spatially detached; deductions are a single aggregate | Connect the scales explicitly, show all five deductions against gross ADD, label the new residual denominator | High / Step 3 |
| Puzzle control feedback | Tiny award dots have generous invisible button areas; selected state changes color without a visible named selection nearby | Equal marks with explicit pressed state and inspectable identity, named inspector, keyboard focus tied to control footprint | High / Step 3 |
| Puzzle selection limits | Decision boundary is static prose; missing records require changing chapter | Select individual unavailable requirements and explain replay consequences in context | High / Step 3 |
| Shared navigation | Header chapter links repeat chapter tabs; mobile header/demo occupy substantial space | Establish compact chapter/tool navigation primitive; retain global navigation during this milestone | Medium / future rollout |
| Overview | Hero has clear photo/type, but its transition into the many-piece Puzzle changes the composition abruptly | Preserve approved hero; improve the Puzzle within it, no new photographic treatment | Medium / Step 3 only below hero |
| Rule Shift | Bone canvas and wide chart compete with a small native selector, then three separate delta figures; mobile adds multiple captions in sequence | Reuse canvas/inspector grammar after approval; retain equal bar lengths and fixed-base warning | Medium / Step 4 |
| Evidence Gap | Proof-track headers, separate missing-input buttons and bottom inspector repeat the vertical pattern of Puzzle | Independent tracks with shared inspector after approval; never connect Test 2 causally to Test 1 | Medium / Step 4 |
| Policy Studio | Dark tool surface, small chart labels and table directly below it differ from bone graphical chapter; mobile labels concatenate long exact amounts | One analytical figure plus exact table disclosure and systematic control sizing | High / Step 5 |
| Fiscal Envelope | Bone waterfall embedded in slate, then separate residual strip, then exact table; narrative and data compete for vertical space | Retain its full analytical depth, align figure/inspector typography and source placement | Medium / Step 5 |
| Awards | Large vertical row spacing and narrow mobile view show few identities; exact amount columns require local horizontal scroll | Document dense record-layout exception with stable numeric alignment and local scroll | Medium / Step 5 |
| ARP | Eight selectable circles, eight text steps and a repeated selected-step panel make three navigation representations | One primary step navigator with contextual detail; preserve all responsibilities/limits | High / Step 5 |
| Source Inspector | Full-height slate dialog has a long definition list, hash, disclosure and citation field; provenance is visually separate from selection | Keep accessible modal/focus behavior; expose precise selected locator locally before opening full source | High / local locator Step 3, dialog Step 5 |
| Alignment / widths | Chapters use a padded bone well while workspaces use the full dark measure; headings and source actions start at different insets | Document common three-zone grid and responsive gutter; apply only Puzzle now | High / staged |
| Borders / radii | Rounded bone canvas, rounded inset inspector, ruled charts, native controls and squared table areas mix visual boundaries | One analytical surface, one hairline inspector boundary, quiet 10px controls; no nested cards | Medium / Step 3 foundation |
| Colors / status | Periwinkle means formula, residual and PASS; apricot means performance and missing evidence; contexts need labels | Explicit semantic labels, dark ink variants on bone; do not rely on hue alone | High / Step 3 foundation |
| Spacing / type | Repeated generous section margins make mobile much longer; headings/amounts vary by component-specific rules | Shared rem scale, clear page/chapter/section/amount roles; document staged adoption | High / Step 3 foundation |
| Source labels | “Source S1”, “Evidence”, “Inspect record limits” and “Inspect source” have different presentation and context | Reusable source action, precise selected locator and inherited-transcription limitation | Medium / Step 3 foundation |

No claim of universal design consistency yet: Steps 4–5 explicitly remain behind approval gates. Preserving the old controls in those views is intentional at this milestone.
